# 컴퓨터 수 표현 및 파이썬 연산 성능 분석 노트

## 1. 고정소수점과 부동소수점 (Fixed-Point vs Floating-Point)

### 1-1. 고정소수점 (Fixed-Point)

* **특징**: 정수부와 소수부의 자릿수를 미리 일정하게 지정하여 고정하는 방식.
* **단점**:
  * **표현 범위가 매우 좁음**: 32비트 기준(부호 1비트, 정수부 15비트, 소수부 16비트)으로 설정하면, 표현 가능한 정수 범위는 -2^{15} sim 2^{15}-1 (-32,768 sim 32,767)에 불과하여 `40000.02` 같은 수조차 표현할 수 없습니다.
  * **공간 낭비**: 정수가 큰 수(예: `227777.12`)를 표현할 때는 소수부에 비해 정수부에 훨씬 큰 비트가 필요한 반면, 고정된 비율 때문에 메모리 공간의 효율적 활용이 어렵습니다.

---

### 1-2. 부동소수점 (Floating-Point)

고정소수점의 공간 낭비를 줄이고, 넓은 실수 표현 범위를 확보하기 위해 등장했습니다.

* **표현 방식**: 소수점이 위치를 바꾸며(부동) 이동하며, 수식을 아래 형태와 같이 표현합니다.
  1.{가수} times {밑수}^{{지수}}
  * 예시: 123.45 rightarrow 1.2345 times 10^2 (부호, 가수, 지수로 구성)
* **특징**:
  * 정수부와 소수부의 위치에 제약을 받지 않고, 제한된 비트 내에서 정밀도를 유지하며 실수를 표현합니다.
  * 고정소수점에 비해 훨씬 넓은 범위를 표현할 수 있어 공간 낭비를 해소합니다.
  * **IEEE 754 32비트(Single Precision) 범위**: 약 -3.4 times 10^{38} sim 3.4 times 10^{38}

---

### 1-3. 부동소수점의 근삿값 저장 오차 (오차 발생 이유)

표현 범위는 대폭 넓어졌지만, 컴퓨터의 제한된 메모리로 인해 실수를 2진수로 변환할 때 소수점 이하가 무한히 반복되는 경우가 존재합니다.

* **이진수 변환 예시**:
  * **딱 떨어지는 수**: 0.625_{(10)} rightarrow 0.101_{(2)}
  * **무한히 반복되는 수**: 0.1_{(10)} rightarrow 0.0001100110011..._{(2)} (무한 순환)
* **결론**: 컴퓨터는 메모리의 한계(가수부 비트 수)까지만 값을 저장하고 나머지는 **반올림/절삭** 처리하므로 연산 오차가 발생할 수밖에 없습니다.
* **연산 오차 예시**: `12.23 + 34.45`
  * 기대값: `46.68`
  * 실제값: `46.680000000000001`

---

### 1-4. IEEE 754 표준 변환 방식

32비트 Single Precision 기준 (부호 1비트, 지수부 8비트, 가수부 23비트)으로 실수를 표현하는 단계입니다.

#### 예시: -118.625 실수 변환 과정

1. **부호 비트 결정**: 음수이므로 최상위 비트는 `1`
2. **이진법 변환**:
   * 118_{(10)} = 1110110_{(2)}
   * 0.625_{(10)} = 0.101_{(2)}
   * 합침: 1110110.101_{(2)}
3. **정규화 (Normalized)**: 소수점을 이동시켜 정수부에 `1`만 남도록 변환합니다.
   * 1110110.101_{(2)} rightarrow 1.110110101_{(2)} times 2^6
4. **가수부 채우기**: 정규화된 2진수는 항상 1.{xxx} 형태이므로, 맨 앞의 `1`을 생략(Implied 1)하고 나머지 소수점을 채웁니다.
   * 가수부(23비트): `11011010100000000000000`
5. **지수부 및 Bias 적용**:
   * 지수가 음수인 경우(2^{-4} 등)를 부호 없이 표현하기 위해 Bias(127)를 더합니다.
   * 지수 6 + {Bias}(127) = 133 rightarrow 10000101_{(2)}
   * *(참고: 0~127 구간은 음수 지수, 128~255 구간은 양수 지수를 의미)*
6. **최종 32비트 표현**:
   ```
   [1] [10000101] [11011010100000000000000]
   부호    지수부(8)         가수부(23)

    ```

## 2. Python 명시적 `for`문 vs `sum()` 연산 방식 비교

실수 배열의 누적 연산(MAC 연산 등)을 수행할 때 두 방식은 동작 방식과 성능, 그리고 오차 보존 측면에서 큰 차이를 보입니다.

### 2-1. 명시적 `for`문 (파이썬 레벨 누적)

```python
for r in range(self.n):
    for c in range(self.n):
        total_sum += self.data[r][c] * pattern.data[r][c]

```

* **동작 특징**: "매 연산마다 객체 포장을 뜯고 다시 포장"
1. **상자 열기**: `total_sum`이 가리키는 `PyFloatObject` 객체 내부에서 8바이트 날것의 실수 데이터(C `double`)를 꺼냅니다.
2. **연산**: CPU ALU에서 덧셈 연산을 수행합니다.
3. **새 상자 만들기**: 연산 결과를 담기 위해 `PyFloatObject` 객체를 힙 메모리에 새로 할당하고 값을 저장한 후 `total_sum`에 재할당합니다.
4. **기존 상자 버리기**: 이전에 쓰던 객체는 참조 카운트가 떨어져 Garbage Collection 대상이 됩니다.


* **성능 및 특성**:
* 루프 단계마다 객체 할당/해제 및 메모리 액세스가 발생하여 오버헤드가 큽니다.
* 매 Step마다 **파이썬 float 객체 레벨에서 발생한 부동소수점 오차(ULP 오프셋)가 중간중간 보존**되는 특징이 있습니다.



#### [참고] 파이썬 실수 객체(`PyFloatObject`)의 구조

파이썬은 단순한 실수 데이터도 C/C++처럼 pure 64비트 실수로 다루지 않고 래핑된 객체(Object)로 관리합니다.

* **C / CPU가 다루는 실제 값**: 8바이트 (64비트 실수)
* **파이썬 실수 객체 헤더**: 총 24바이트 오버헤드 발생
* 참조 카운터 (`ob_refcnt`): 8바이트
* 타입 포인터 (`ob_type`): 8바이트
* 실제 실수 값 (`ob_fval`): 8바이트



---

### 2-2. `sum()` 내장 함수 방식 (C-Level 파이프라인)

```python
total_sum = sum(
    self.data[r][c] * pattern.data[r][c]
    for r in range(self.n) for c in range(self.n)
)

```

* **동작 특징**: "CPU 레지스터 위에서 직접 누적 후 마지막에 일괄 포장"
1. **C 언어 내부 구현**: 파이썬 `sum()` 내부는 CPython C-API로 구현되어 있어 루프 중간에 `PyFloatObject` 객체를 매번 새로 만들지 않습니다.
2. **CPU 레지스터 활용**: 중간 누적값을 파이썬 객체로 변환하지 않고, C 레벨의 고속 레지스터/누적기(C `double`) 상에서 64비트 날것의 수로 계속해서 가산합니다.
3. **최종 포장**: 모든 루프가 끝난 **맨 마지막 순간에 단 한 번만** `PyFloatObject` 객체로 변환하여 반환합니다.


* **성능 및 특성**:
* 연산 속도가 매우 빠르고 효율적입니다.
* 단, C-Level 레지스터에서 연속 누적되는 과정에서 IEEE 754 반올림 규칙(Round-to-Nearest-Even)에 의해 하위 미세 오차가 수렴 정리되는 특성을 보입니다.
