# [Dreamhack / x86-64] 어셈블리 문제 풀이 및 코드 복호화 정리

---

## Problem 1. x86-64 메모리 루프 복호화 코드 분석

### 1. 문제 조건 및 초기 상태

* **초기 레지스터 상태**
  * `rcx = 0x0`
  * `rdx = 0x0`
  * `rsi = 0x400000` (복호화 대상 데이터의 시작 주소)

* **메모리 데이터 (HEX)**
  * `0x400000`: `0x67  0x55  0x5c  0x53  0x5f  0x5d  0x55  0x10`
  * `0x400008`: `0x44  0x5f  0x10  0x51  0x43  0x43  0x55  0x5d`
  * `0x400010`: `0x52  0x5c  0x49  0x10  0x47  0x5f  0x42  0x5c`
  * `0x400018`: `0x54  0x11  0x00  0x00  0x00  0x00  0x00  0x00`

---

### 2. 어셈블리 코드 분석 및 핵심 로직

```assembly
1: mov dl, BYTE PTR [rsi + rcx]  ; [rsi + rcx] 주소에서 1바이트를 dl에 로드
2: xor dl, 0x30                  ; dl 레지스터 값과 키(0x30)를 XOR 연산
3: mov BYTE PTR [rsi + rcx], dl  ; 복호화된 1바이트 데이터를 메모리에 다시 저장
4: inc rcx                       ; 인덱스(rcx) 1 증가
5: cmp rcx, 0x19                 ; rcx와 0x19 (10진수 25) 비교
6: jg end                        ; rcx > 0x19 이면 루프 종료 (0x0 ~ 0x19 총 26바이트 연산)
7: jmp 1                         ; 다음 바이트 복호화를 위해 루프 상단으로 이동

```

* **핵심 분석 요약**: `0x400000` 주소부터 총 **25바이트** 동안 메모리의 각 바이트 원소들을 `0x30`(`0011 0000_2`) 키값과 XOR 연산하여 복호화하는 어셈블리 루프문입니다.

---

### 3. Step-by-Step 비트 연산 검증

#### 1) `rcx = 0` (Loop 1)

* 원본 메모리 데이터: `[0x400000] = 0x67` (`0110 0111_2`)
* XOR 연산 계산:

$$\begin{array}{rcc}     & 0110\ 0111_2 & (0x67) \\ \oplus & 0011\ 0000_2 & (0x30) \\ \hline     & 0101\ 0111_2 & (\mathbf{0x57}) \end{array}$$

* `[0x400000]` 데이터가 `0x57` ('W')로 복호화됩니다.
* `inc rcx` 수행 $\rightarrow$ `rcx = 1`, `cmp` 조건을 만족하므로 다음 루프 진행.

#### 2) `rcx = 1` (Loop 2)

* 원본 메모리 데이터: `[0x400001] = 0x55` (`0101 0101_2`)
* XOR 연산 계산:

$$\begin{array}{rcc}     & 0101\ 0101_2 & (0x55) \\ \oplus & 0011\ 0000_2 & (0x30) \\ \hline     & 0110\ 0101_2 & (\mathbf{0x65}) \end{array}$$

* `[0x400001]` 데이터가 `0x65` ('e')로 복호화됩니다.

---

### 4. 복호화 결과 및 ASCII 변환표

| 주소 | Encrypted Value | Key | Decrypted Value (HEX) | ASCII |
| --- | --- | --- | --- | --- |
| `0x400000` | `0x67` | $\oplus\ 0x30$ | `0x57` | **'W'** |
| `0x400001` | `0x55` | $\oplus\ 0x30$ | `0x65` | **'e'** |
| `0x400002` | `0x5c` | $\oplus\ 0x30$ | `0x6c` | **'l'** |
| `0x400003` | `0x53` | $\oplus\ 0x30$ | `0x6c` | **'c'** |
| `0x400004` | `0x5f` | $\oplus\ 0x30$ | `0x6f` | **'o'** |
| `0x400005` | `0x5d` | $\oplus\ 0x30$ | `0x6d` | **'m'** |
| `0x400006` | `0x55` | $\oplus\ 0x30$ | `0x65` | **'e'** |
| `0x400007` | `0x10` | $\oplus\ 0x30$ | `0x20` | **' '** *(Space)* |

* **결과**: `0x57, 0x65, 0x6c, 0x63, 0x6f, 0x6d, 0x65, 0x20...` 순으로 풀리면서 최종적으로 "Welcome..."으로 시작하는 평문 문자열이 복호화됩니다.

## Problem 2. x86-64 `sys_write` 시스템 콜 출력 분석

### 1. 디스어셈블리 코드 및 메모리 구조

```assembly
main:
    push rbp
    mov rbp, rsp
    mov esi, 0xf                 ; esi = 15 (출력할 바이트 수)
    mov rdi, 0x400500            ; rdi = 0x400500 (출력 대상 버퍼 주소)
    call 0x400497 <write_n>      ; write_n 함수 호출
    mov eax, 0x0
    pop rbp
    ret

write_n:
    push rbp
    mov rbp, rsp
    mov QWORD PTR [rbp-0x8], rdi ; 인자 1 (0x400500)을 스택 [rbp-8]에 레지스터 보관
    mov DWORD PTR [rbp-0xc], esi ; 인자 2 (15)를 스택 [rbp-12]에 레지스터 보관
    xor rdx, rdx                 ; rdx 0으로 초기화
    mov edx, DWORD PTR [rbp-0xc] ; rdx = 15 (syscall 인자 3: count)
    mov rsi, QWORD PTR [rbp-0x8] ; rsi = 0x400500 (syscall 인자 2: buf)
    mov rdi, 0x1                 ; rdi = 1 (syscall 인자 1: fd = stdout)
    mov rax, 0x1                 ; rax = 1 (sys_write 시스템 콜 번호)
    syscall                      ; write(1, 0x400500, 15) 실행
    pop rbp
    ret

```

* **메모리 상의 QWORD 데이터**
* `0x400500`: `0x3037207964343372`
* `0x400508`: `0x003f367562336420`



---

### 2. `syscall` 인자 바인딩 해석

x86-64 리눅스 System V ABI 매커니즘에 따른 레지스터 세팅 분석:

* **`rax = 0x01`**: `sys_write` 시스템 콜 호출
* **`rdi = 0x01`**: File Descriptor `1` (`stdout`, 표준 출력)
* **`rsi = 0x400500`**: 출력할 문자열이 위치한 메모리 주소
* **`rdx = 15 (0xf)`**: 출력할 데이터의 크기 (15 Bytes)

$$\text{syscall}\ \rightarrow\ \text{write}(\text{fd}=1,\ \text{buf}=0x400500,\ \text{count}=15)$$

---

### 3. 리틀 엔디언(Little-Endian) 바이트 파싱 및 ASCII 변환

x86-64 시스템은 **Little-Endian** 모드로 작동하므로, 64비트 레지스터/메모리 상의 데이터는 낮은 주소에 최하위 바이트(LSB)가 위치하게 됩니다.

#### 1) `0x400500` 주소 파싱 (앞 8바이트)

* QWORD 데이터: `0x3037207964343372`
* **메모리 오프셋 순서대로 재정렬 (낮은 주소 $\rightarrow$ 높은 주소)**:
`0x72` $\rightarrow$ `0x33` $\rightarrow$ `0x34` $\rightarrow$ `0x64` $\rightarrow$ `0x79` $\rightarrow$ `0x20` $\rightarrow$ `0x37` $\rightarrow$ `0x30`

| HEX | ASCII |
| --- | --- |
| `0x72` | `'r'` |
| `0x33` | `'3'` |
| `0x34` | `'4'` |
| `0x64` | `'d'` |
| `0x79` | `'y'` |
| `0x20` | `' '` |
| `0x37` | `'7'` |
| `0x30` | `'0'` |

* **1차 변환 결과**: `"r34dy 70"` (8 Bytes)

---

#### 2) `0x400508` 주소 파싱 (뒤 7바이트)

* 전체 15바이트 중 남은 **7바이트**만 읽습니다.
* QWORD 데이터: `0x003f367562336420`
* **메모리 오프셋 순서대로 재정렬**:
`0x20` $\rightarrow$ `0x64` $\rightarrow$ `0x33` $\rightarrow$ `0x62` $\rightarrow$ `0x75` $\rightarrow$ `0x36` $\rightarrow$ `0x3f`

| HEX | ASCII |
| --- | --- |
| `0x20` | `' '` |
| `0x64` | `'d'` |
| `0x33` | `'3'` |
| `0x62` | `'b'` |
| `0x75` | `'u'` |
| `0x36` | `'6'` |
| `0x3f` | `'?'` |

* **2차 변환 결과**: `" d3bu6?"` (7 Bytes)

---

### 4. 최종 출력값 (Flag / String)

두 영역의 파싱 결과를 연결한 최종 출력 문자열:

```text
r34dy 70 d3bu6?

```
