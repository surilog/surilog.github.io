# [Dreamhack] rev-basic-6 핵심 연산 구조 분석

## 1. 개요 및 함수 분석

### `main()` 함수 제어 구조

```c
int __fastcall main(int argc, const char **argv, const char **envp)
{
    char v4[256];

    memset(v4, 0, sizeof(v4));
    sub_1400011B0("Input : ", argv, envp);
    sub_140001210("%256s", v4);
    if ( (unsigned int)sub_140001000((__int64)v4) )
        puts("Correct");
    else
        puts("Wrong");
    return 0;
}

```

---

### `sub_140001000()` 조건식 분석

```c
__int64 __fastcall sub_140001000(__int64 a1)
{
    int i;

    for ( i = 0; (unsigned __int64)i < 0x12; ++i )
    {
        if ( byte_140003020[*(unsigned __int8 *)(a1 + i)] != byte_140003000[i] )
            return 0LL;
    }
    return 1LL;
}

```

* **조건식**: `byte_140003020[(unsigned __int8)a1[i]] == byte_140003000[i]` ($i = 0 \sim 17$)
* **메모리 배열 표기 단순화**:
* $data1 = \text{byte\_140003020}$ (치환 테이블 / S-Box 역할)
* $data2 = \text{byte\_140003000}$ (비교 대상 정답 테이블)


* **단순화된 검증식**:

$$data1[a1[i]] == data2[i]$$

## 2. 연산 단계별 추적 및 인덱스 역산 ($i = 0 \sim 2$)

`data1` 배열은 256바이트 크기의 1:1 대치(Substitution) 테이블입니다. 배열 인덱스가 `0`부터 시작(0-based Indexing)하는 특성을 고려하여 $data2[i]$ 값이 $data1$ 배열의 몇 번째 인덱스 오프셋에 존재하는지 추적합니다.

### 1) $i = 0$ 일 때 (`data2[0] = 0x00`)

$$data1[a1[0]] == 0x00$$

* $data1$ 배열에서 `0x00` 데이터는 83번째 원소에 위치합니다.
* **0-based 인덱스 계산**: $83 - 1 = \mathbf{82}$ (`0x52`)
* **결과**: $a1[0] = 0 \times 52$ (ASCII 문자 `'R'`)

### 2) $i = 1$ 일 때 (`data2[1] = 0x4D`)

$$data1[a1[1]] == 0x4D$$

* $data1$ 배열에서 `0x4D` 데이터는 102번째 원소에 위치합니다.
* **0-based 인덱스 계산**: $102 - 1 = \mathbf{101}$ (`0x65`)
* **결과**: $a1[1] = 0 \times 65$ (ASCII 문자 `'e'`)

### 3) $i = 2$ 일 때 (`data2[2] = 0x51`)

$$data1[a1[2]] == 0x51$$

* $data1$ 배열에서 `0x51` 데이터는 113번째 원소에 위치합니다.
* **0-based 인덱스 계산**: $113 - 1 = \mathbf{112}$ (`0x70`)
* **결과**: $a1[2] = 0 \times 70$ (ASCII 문자 `'p'`)

---

### Step-by-Step 인덱스 매핑 요약

| 루프 ($i$) | `data2[i]` (Target) | `data1` 원소 순서 | **0-based Index (Dec)** | **HEX** | **ASCII** |
| --- | --- | --- | --- | --- | --- |
| **0** | `0x00` | 83번째 | **82** | `0x52` | `'R'` |
| **1** | `0x4D` | 102번째 | **101** | `0x65` | `'e'` |
| **2** | `0x51` | 113번째 | **112** | `0x70` | `'p'` |

## 3. 알고리즘 의사코드 (Pseudocode Concept)

```python
# S-Box 루크업 테이블(data1) 기반 인덱스 역산 의사코드

for i in range(18):
    target_val = data2[i]
    
    # data1(S-Box) 배열 내에서 target_val이 존재하는 0-based 인덱스를 추출
    # 해당 인덱스 값이 곧 입력 문자 a1[i]의 ASCII 코드가 됨
    ascii_code = data1.index(target_val)
    a1.append(ascii_code)

```

---

## 4. 핵심 정리

1. **S-Box 인덱싱 매커니즘**: 본 문제는 입력 문자의 ASCII 값 자체를 오프셋 주소로 사용하여 `data1` 메모리의 원소를 참조하는 치환 구조를 갖습니다.
2. **0-based 역산 알고리즘**: $data1[x] = y \implies x = data1^{-1}(y)$ 관계에 따라 `data2[i]` 값이 위치한 0-based 인덱스 번호를 구하면 본래의 입력 문자열을 순차적으로 복원할 수 있습니다.
