# 1. 컴퓨터 구조 (Computer Architecture)

컴퓨터 구조는 CPU, 메모리, 입출력 장치 등 하드웨어 구성 요소가 어떻게 설계되고 상호작용하는지를 다루며, 프로그램이 기계어 수준에서 실행되는 전체 파이프라인을 다루는 분야입니다.

* **컴퓨터 기능 구조 설계**: 컴퓨터가 연산을 효율적으로 하기 위해 어떠한 구조를 가질지 결정하는 영역.
  * 폰 노이만 구조 (명령어와 데이터를 구분 없이 하나의 메모리에 저장)
  * 하버드 구조 (명령어 메모리와 데이터 메모리를 물리적으로 분리)
  * 수정된 하버드 구조 (캐시 메모리 단에서는 분리, 주 메모리 단에서는 통합 관리)

```text
[ CPU (ALU, Register, Control Unit, Cache) ] <---> [ Memory (RAM) ]

```

---

## 1-1. 중앙처리장치 (CPU)

프로그램의 연산을 처리하고 시스템을 제어하는 컴퓨터의 핵심 장치입니다. (프로세스의 코드를 페치(Fetch), 디코드(Decode), 실행(Execute) 및 저장하는 일련의 과정을 담당)

* **ALU (Arithmetic Logic Unit)**: 산술 연산(덧셈, 뺄셈 등) 및 논리 연산(AND, OR 등) 수행
* **제어장치 (Control Unit)**: 명령어를 해석하고 각 장치에 제어 신호를 전달
* **Register**: CPU 내부에 위치한 초고속 임시 저장 장치

---

## 1-2. 기억장치 및 버스 (BUS)

* **주기억장치 (RAM)**: 프로세스가 실행되는 동안 필요한 데이터 및 코드 임시 저장
* **보조기억장치 (HDD/SSD)**: 운영체제, 파일, 프로그램 등을 비휘발성으로 장기 보관
* **버스 (BUS)**: 부품 간 데이터 및 제어 신호를 주고받는 통로
* 데이터 버스 / 주소 버스 / 제어 버스



>  **CPU 내부에 레지스터가 필수적인 이유**
> CPU의 연산 속도에 비해 RAM 데이터 접근 속도는 현저히 느려 **병목 현상(Bottleneck)**이 발생합니다.
> $\rightarrow$ 이를 완화하기 위해 **CPU 내부 레지스터 및 캐시(L1/L2/L3)**를 활용하여 데이터 전달 속도의 갭을 메웁니다.

---

## 1-3. 명령어 집합 구조 (Instruction Set Architecture, ISA)

CPU가 이해할 수 있는 기계어 명령어의 집합으로, 소프트웨어와 하드웨어 간의 인터페이스 역할을 정의합니다.

* **CISC (Complex Instruction Set Computer)**: 복잡하고 다양한 명령어를 제공하여 메모리 효율성 향상 (예: x86, x86-64)
* **RISC (Reduced Instruction Set Computer)**: 명령어 집합을 단순화하여 전력 효율 및 고속 연산 제공 (예: ARM, MIPS, RISC-V)

---

## 1-4. x86-64 아키텍처 및 WORD 개념

* **x86-64 아키텍처**: 32비트 x86 구조와 호환성을 유지하면서 확정한 64비트 아키텍처 (AMD64 / Intel64).
* **$n$-비트 아키텍처의 의미**: 32비트, 64비트에서 숫자는 CPU가 한 번에 처리할 수 있는 데이터 단위(Word Size)를 의미합니다.
* **WORD의 하드웨어적 의미**:
1. 레지스터 1개의 크기
2. ALU의 기본 연산 데이터 처리 단위
3. 표현 가능한 가상 주소 공간의 폭 ($2^{64}$ 바이트 주소 공간)
4. 데이터 버스(BUS)의 대역폭



>  **어셈블리 표준에서의 WORD 명칭 주의**
> x86/x64 어셈블리 구문에서는 레거시 16비트 시절과의 호환성을 위해 데이터 단위를 아래와 같이 고정하여 표기합니다.
> * `BYTE` = 1 바이트 (8비트)
> * `WORD` = 2 바이트 (16비트)
> * `DWORD` (Double Word) = 4 바이트 (32비트)
> * `QWORD` (Quad Word) = 8 바이트 (64비트)
> 
>

## 1-5. x86-64 레지스터 (Register)

### ① 범용 레지스터 (General Purpose Register)

데이터 연산, 주소 계산, 임시 저장 등 다목적으로 사용됩니다. x64에서는 레지스터 크기가 8바이트(64비트)로 확장되었습니다.

| 레지스터 이름 | 주요 역할 및 별칭 | x64 주요 용도 |
| --- | --- | --- |
| **RAX** | Accumulator Register | 함수 반환 값(Return Value) 저장, 산술 연산 |
| **RBX** | Base Register | 주소 지정 보조 (x64에서는 주 용도 자율화) |
| **RCX** | Counter Register | 반복문/Shift 연산 카운터, **x64 4번째 함수 인자** (Win64 ABI: RCX) |
| **RDX** | Data Register | 연산 보조, **x64 3번째 함수 인자** (Win64 ABI: RDX) |
| **RSI** | Source Index | 데이터 복사 시 원본 주소, **x64 2번째 함수 인자** (System V ABI) |
| **RDI** | Destination Index | 데이터 복사 시 목적지 주소, **x64 1번째 함수 인자** (System V ABI) |
| **RSP** | Stack Pointer | 현재 스택 최상단(Top) 메모리 주소 지시 |
| **RBP** | Stack Base Pointer | 현재 스택 프레임의 기준점(Base) 주소 지시 |
| **R8 ~ R15** | Extended Registers | x64에서 새로 추가된 범용 레지스터 |

#### 레지스터 하위 비트 호환 구조

하위 호환성을 위해 64비트 레지스터의 일부 비트 영역에만 독립적으로 접근할 수 있습니다.

```text
[                     RAX (64-bit)                    ]
                      [          EAX (32-bit)         ]
                                 [     AX (16-bit)    ]
                                 [ AH (8) ][ AL (8) ]

```

---

### ② 세그먼트 레지스터 (Segment Register)

메모리를 세그먼트 단위로 분할하여 접근할 수 있게 해주는 16비트 레지스터입니다. (x64 보호 모드/롱 모드에서는 메모리 보호 및 특수 용도로 활용됨)

| 이름 | 주 용도 |
| --- | --- |
| **CS** (Code Segment) | 실행할 코드 영역의 세그먼트 지시 |
| **DS** (Data Segment) | 데이터 영역의 세그먼트 지시 |
| **SS** (Stack Segment) | 스택 영역의 세그먼트 지시 |
| **ES / FS / GS** | 추가 데이터 세그먼트 (Windows x64에서는 **FS/GS**가 TEB/PEB 구조체 주소를 가리킴) |

---

### ③ 명령어 포인터 레지스터 (Instruction Pointer Register)

* CPU가 다음으로 실행해야 할 기계어 명령어의 주소를 가리킵니다.
* x86-64 아키텍처에서는 **RIP**이며, 크기는 8바이트(64비트)입니다.

---

### ④ 플래그 레지스터 (RFLAGS)

* CPU 연산 수행 직후의 상태나 제어 정보를 비트 단위로 저장하는 64비트 레지스터입니다.
* 조건문(`cmp`, `test` 등) 수행 후 분기 명령(`je`, `jne`, `jg` 등)을 결정하는 데 쓰입니다.

#### 주요 상태 플래그 (Status Flags)

| 플래그 | 의미 | 발생 조건 예시 |
| --- | --- | --- |
| **CF** (Carry Flag) | Carry / Borrow | 부호 없는 수(Unsigned)의 연산 결과가 비트 범위를 초과/미달한 경우 |
| **ZF** (Zero Flag) | Zero | 연산 결과가 정확히 `0`인 경우 |
| **SF** (Sign Flag) | Sign | 연산 결과가 음수(최상위 비트 MSB가 `1`)인 경우 |
| **OF** (Overflow Flag) | Overflow | 부호 있는 수(Signed)의 연산 결과가 표현 범위를 벗어난 경우 |

# 2. Windows 메모리 레이아웃 (Memory Layout)

운영체제는 실행되는 프로그램에게 독립된 **가상 메모리(Virtual Memory)** 공간을 할당합니다. Windows 가상 메모리는 파일 섹션(PE Section) 기반 세그먼트와 동적 메모리 영역으로 구성됩니다.

---

## 2-1. 프로세스 메모리 섹션 (PE Section)

Windows의 실행 파일(PE, Portable Executable)은 속성별로 구분된 세그먼트(섹션) 단위로 가상 메모리에 매핑됩니다.

* **.text**: 실행 가능한 기계 코드가 위치하는 영역 (`R-X` 권한)
* **.data**: 초기화된 전역 변수 및 정적(static) 변수가 위치하는 영역 (`RW-` 권한)
* **.rdata**: 읽기 전용 상수, 문자열 리터럴, IAT(Import Address Table) 등이 위치하는 영역 (`R--` 권한)

---

## 2-2. 세그먼트별 C 언어 코드 매핑 예시

```c
#include <stdio.h>

int data_num = 31337;                  // .data (초기화된 전역변수)
char data_rwstr[] = "writable_data";   // .data (수정 가능한 전역 배열)
const char data_rostr[] = "readonly";  // .rdata (전역 상수)

int main() {                           // .text (실행 코드)
    char *str_ptr = "readonly_literal"; // str_ptr 자체는 스택, 문자열 리터럴은 .rdata
    return 0;
}

```

---

## 2-3. 동적 메모리 영역 (스택과 힙)

### ① 스택 (Stack)

* 함수 호출 시 **지역 변수**, **매개변수**, **리턴 주소(Return Address)** 등이 할당되는 공간입니다.
* 높은 주소에서 낮은 주소 방향으로 확장됩니다.

### ② 힙 (Heap)

* 실행 중 동적으로 메모리를 할당(`malloc()`, `new`)받아 사용하는 공간입니다.
* 낮은 주소에서 높은 주소 방향으로 확장됩니다.

---

## 2-4. 메모리 영역 종합 요약 표

| 영역 / 섹션 | 주요 역할 | 권한 | 주요 사용 예시 및 확장 방향 |
| --- | --- | --- | --- |
| **.text** | 실행 가능한 기계어 코드 | `R-X` | `main()` 및 사용자 정의 함수 |
| **.data** | 초기화된 전역/정적 변수 | `RW-` | `int a = 10;` |
| **.rdata** | 초기화된 전역 상수 및 리터럴 | `R--` | `"Hello World"`, `const` 변수 |
| **스택 (Stack)** | 임시 데이터 (함수 프레임) | `RW-` | 지역 변수, 리턴 주소 (**고주소 $\rightarrow$ 저주소**) |
| **힙 (Heap)** | 동적 할당 메모리 | `RW-` | `malloc()` 할당 영역 (**저주소 $\rightarrow$ 고주소**) |

```

```
