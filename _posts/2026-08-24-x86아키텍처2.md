# x86-64 어셈블리 Part 2: 함수, 스택 및 시스템 콜 노트

## 1. 함수 / 프로시저 (Function / Procedure)

어셈블리어에서 **함수(Function)**란 프로그램이 처리해야 할 명령어들의 집합을 의미하며, 독립된 코드 블록으로 존재합니다.

* **개념**: Label로 시작 위치를 표시하며, `call` 명령어를 통해 해당 위치로 분기(Branch)하여 실행됩니다.
* **용어**: 서브루틴(Subroutine), 프로시저(Procedure), 함수(Function)라는 용어가 혼용되어 사용됩니다.
* **호출 구조**:
  * **Caller (호출자)**: `call` 명령어로 피호출 함수를 호출하고, 함수의 실행 완료를 기다립니다.
  * **Callee (피호출자)**: 자신의 로직을 수행한 후 `ret` 명령어를 통해 Caller가 원래 수행하던 다음 코드 위치로 복귀합니다.

## 2. 스택(Stack) 개념 및 관련 명령어

### 2-1. 스택(Stack)의 구조적 특징

* **자료구조**: LIFO(Last In, First Out / 후입선출) 구조로 동작합니다.
* **메모리 증가 방향**: x86-64 아키텍처의 스택은 **높은 메모리 주소 $\rightarrow$ 낮은 메모리 주소** (Downwards) 방향으로 자랍니다.
  * 데이터 삽입(`push`): 메모리 주소 **감소** ($\text{rsp} \leftarrow \text{rsp} - 8$)
  * 데이터 제거(`pop`): 메모리 주소 **증가** ($\text{rsp} \leftarrow \text{rsp} + 8$)
* **스택 포인터 (`rsp`)**: 스택 영역의 **최상단(Top)** 주소를 가리키는 전용 레지스터입니다.

---

### 2-2. `push val`

스택의 최상단에 값을 저장하는 명령어입니다.

* **형태**: `push val`
* **내부 동기적 연산**:
  $$\text{rsp} \leftarrow \text{rsp} - 8$$
  $$[\text{rsp}] \leftarrow \text{val}$$

#### `push 0x31337` 실행 예시

| 구분 | 실행 전 (Before) | 실행 후 (After) |
| :--- | :--- | :--- |
| **Register** | `rsp = 0x7fffffffc400` | `rsp = 0x7fffffffc3f8` |
| **Stack** | `0x7fffffffc400`: `0x0000000000000000` $\leftarrow$ `rsp` | `0x7fffffffc3f8`: `0x0000000000031337` $\leftarrow$ `rsp`<br>`0x7fffffffc400`: `0x0000000000000000` |

---

### 2-3. `pop reg`

스택 최상단의 값을 꺼내 지정한 레지스터에 복원하고, `rsp` 주소를 증가시킵니다.

* **형태**: `pop reg`
* **내부 동기적 연산**:
  $$\text{reg} \leftarrow [\text{rsp}]$$
  $$\text{rsp} \leftarrow \text{rsp} + 8$$

#### `pop rax` 실행 예시 (위 push 상태 연계)

| 구분 | 실행 전 (Before) | 실행 후 (After) |
| :--- | :--- | :--- |
| **Register** | `rax = 0x0`<br>`rsp = 0x7fffffffc3f8` | `rax = 0x31337`<br>`rsp = 0x7fffffffc400` |
| **Stack** | `0x7fffffffc3f8`: `0x0000000000031337` $\leftarrow$ `rsp`<br>`0x7fffffffc400`: `0x0000000000000000` | `0x7fffffffc3f8`: `0x0000000000031337` *(Dummy)*<br>`0x7fffffffc400`: `0x0000000000000000` $\leftarrow$ `rsp` |

---

## 3. 함수 제어 명령어 (`call`, `leave`, `ret`)

함수 제어 명령어는 **함수 프롤로그(Prologue)**와 **에필로그(Epilogue)**를 형성하며 프로그램 제어 흐름(Control Flow)을 관장합니다.

### 3-1. `call addr`

* **역할**: 지정한 주소 `addr`로 분기하여 함수를 호출합니다. 복귀할 주소(Return Address)를 스택에 자동으로 보관합니다.
* **내부 연산**:
  $$\text{push}\ \text{Return\_Address}\ (\text{next}\ \text{rip})$$
  $$\text{jmp}\ \text{addr}$$

#### `call 0x401000` 실행 예시

| 구분 | 실행 전 (Before) | 실행 후 (After) |
| :--- | :--- | :--- |
| **Register** | `rip = 0x400000` *(Next RIP: 0x400005)*<br>`rsp = 0x7fffffffc400` | `rip = 0x401000`<br>`rsp = 0x7fffffffc3f8` |
| **Stack** | `0x7fffffffc400`: `0x0000000000000000` $\leftarrow$ `rsp` | `0x7fffffffc3f8`: `0x0000000000400005` *(RET)* $\leftarrow$ `rsp`<br>`0x7fffffffc400`: `0x0000000000000000` |

---

### 3-2. `leave` (함수 에필로그 단계 1)

* **역할**: 현재 함수가 사용하던 스택 프레임(Stack Frame)을 해제하고, 이전 함수의 `rbp`를 복원합니다.
* **내부 연산**:
  $$\text{mov}\ \text{rsp},\ \text{rbp}$$
  $$\text{pop}\ \text{rbp}$$

#### `leave` 실행 예시

| 구분 | 실행 전 (Before) | 실행 후 (After) |
| :--- | :--- | :--- |
| **Register** | `rsp = 0x7fffffffc400`<br>`rbp = 0x7fffffffc480` | `rsp = 0x7fffffffc488`<br>`rbp = [0x7fffffffc480]` *(Saved RBP)* |

---

### 3-3. `ret` (함수 에필로그 단계 2)

* **역할**: 스택 최상단에 저장된 Return Address를 꺼내 `rip` 레지스터에 저장함으로써 호출 이전의 위치로 돌아갑니다.
* **내부 연산**:
  $$\text{pop}\ \text{rip}$$

#### `ret` 실행 예시

| 구분 | 실행 전 (Before) | 실행 후 (After) |
| :--- | :--- | :--- |
| **Register** | `rip = 0x401008`<br>`rsp = 0x7fffffffc3f8` *(Top = 0x400005)* | `rip = 0x400005`<br>`rsp = 0x7fffffffc400` |

## 4. 함수 호출 규약 (Calling Convention)

아키텍처(32bit vs 64bit) 및 OS 컴파일러 표준에 따라 함수에 인자를 전달하는 방식과 스택 프레임을 정리하는 주체가 다릅니다.

### ① x86 (32-bit: cdecl 규약)
* **인자 전달 방식**: 오른쪽 인자부터 왼쪽 방향으로 스택에 `push`하여 전달합니다.
* **스택 정리**: **Caller(호출자)**가 함수 반환 직후 `add esp, N`을 통해 직접 스택을 보정합니다.

```assembly
; cdecl 예시
add_func:
    push ebp
    mov ebp, esp
    mov eax, [ebp + 8]    ; 1번째 인자 (arg1)
    add eax, [ebp + 12]   ; 2번째 인자 (arg2)
    leave
    ret

_start:
    push dword 20         ; 2번째 인자 push
    push dword 10         ; 1번째 인자 push
    call add_func
    add esp, 8            ; Caller가 직접 스택 보정 (4bytes * 2 = 8)

```

### ② x64 (64-bit: System V AMD64 ABI / Linux 기준)

* **인자 전달 방식**: 앞선 **6개 정수형 인자는 범용 레지스터**를 통해 직접 전달하며, 7번째 인자부터 스택을 활용합니다.
* **순서**: `rdi` $\rightarrow$ `rsi` $\rightarrow$ `rdx` $\rightarrow$ `rcx` $\rightarrow$ `r8` $\rightarrow$ `r9`


* **스택 정리**: 레지스터를 주로 활용하므로 별도의 스택 정리 작업이 최소화됩니다.

```assembly
; System V AMD64 ABI 예시
add_func:
    push rbp
    mov rbp, rsp
    mov rax, rdi          ; rdi = 1번째 인자 (10)
    add rax, rsi          ; rsi = 2번째 인자 (20)
    pop rbp
    ret

_start:
    mov rdi, 10           ; 1번째 인자 설정
    mov rsi, 20           ; 2번째 인자 설정
    call add_func

```

## 5. 리눅스 시스템 콜 (System Call)

유저 모드(User Mode) 애플리케이션이 파일 입출력, 프로세스 생성, 메모리 할당 등 커널(Kernel)의 특권 명령을 안전하게 요청하기 위해 사용하는 인터페이스입니다.

| 구분 | x86 (32-bit) | x64 (64-bit) |
| --- | --- | --- |
| **트랩/호출 명령어** | `int 0x80` | `syscall` |
| **Syscall 번호 레지스터** | `eax` | `rax` |
| **인자 전달 순서** | `ebx`, `ecx`, `edx`, `esi`, `edi`, `ebp` | `rdi`, `rsi`, `rdx`, `r10`, `r8`, `r9` |

>  **주의**: 64bit C standard 라이브러리 함수 호출 시에는 4번째 인자로 `rcx`를 사용하지만, **Direct System Call(`syscall`) 사용 시 4번째 인자는 `r10` 레지스터**를 사용합니다. (커널 내부 트랩 제어 특성 때문)

---

### x64 주요 리눅스 시스템 콜 테이블 (System Call Table)

포네이블(Pwnable) 및 바이너리 분석 시 빈번하게 참조되는 필수 시스템 콜 모음입니다.

| Syscall | `rax` | `arg0 (rdi)` | `arg1 (rsi)` | `arg2 (rdx)` | 비고 / 설명 |
| --- | --- | --- | --- | --- | --- |
| **`read`** | `0x00` | `unsigned int fd` | `char *buf` | `size_t count` | 파일/소켓/표준입력(`0`) 읽기 |
| **`write`** | `0x01` | `unsigned int fd` | `const char *buf` | `size_t count` | 파일/소켓/표준출력(`1`) 쓰기 |
| **`open`** | `0x02` | `const char *filename` | `int flags` | `umode_t mode` | 파일 열기 |
| **`close`** | `0x03` | `unsigned int fd` | - | - | 파일 디스크립터 닫기 |
| **`execve`** | `0x3b` | `const char *filename` | `char *const *argv` | `char *const *envp` | 프로그램 실행 (쉘 획득 시 필수) |

---

##  요약 및 핵심 정리

1. **스택의 제어 법칙**: x86-64 스택은 메모리 주소가 내려가는 방향으로 자라며, `rsp`는 최상단을 포인트합니다.
2. **함수의 주기**: `call` 수행 시 복귀 주소가 스택에 쌓이고, 함수 종료 시 `leave`로 스택 프레임을 해제한 후 `ret`으로 복귀 주소를 `rip`에 주입합니다.
3. **인자 전달 매커니즘**: x64 Linux 환경에서는 `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` 순으로 인자를 넘깁니다.
4. **Syscall 활용**: 64비트 환경에서 커널 서비스를 직접 호출할 땐 `rax`에 번호를 넣고 `syscall` 명령어를 수행합니다.
